## 1. 이미 반영된 코드 변경 (검증 완료)

모두 `node --check` 문법 검사, `words.json` 스키마 검사, `npm run build` 통과 상태입니다.

### 1-1. `index.html` — Firebase Analytics 계측 신설

배경: 분석 도구가 한 줄도 없어 출시 후 이탈 지점을 알 방법이 없었습니다.

```js
// 삽입 위치: const db = getFirestore(app); 직후
import { getAnalytics, logEvent, isSupported } from ".../firebase-analytics.js";
let analytics = null; const _evQueue = [];
function track(name, params = {}) { ... }   // window.track 으로도 노출
```

- `isSupported()` + try/catch 이중 격리 — GA 미연동·구형 웹뷰·광고차단 어떤 경우에도 학습 흐름이 막히지 않습니다.
- 초기화 완료 전 발생한 이벤트는 최대 50건까지 큐에 보관 후 일괄 전송합니다.
- `measurementId`는 config에 넣지 않았습니다. SDK가 서버에서 동적으로 가져옵니다.

**심은 이벤트 8종**

| 이벤트 | 호출 위치 | 파라미터 |
|---|---|---|
| `login` | 구글·익명·이메일 로그인 성공 지점 | `method` |
| `sign_up` | `createUserWithEmailAndPassword` 성공 후 | `method` |
| `study_start` | `startSession()` 초입 | `topic`, `target_count` |
| `study_complete` | 결과 화면 렌더 직후 | `topic`, `words`, `correct_first_try`, `accuracy`, `shards`, `new_words`, `streak`, `level` |
| `placement_start` | `startPlacement()` | — |
| `placement_complete` | `showPlacementResult()` | `tier`, `altitude`, `rating` |
| `word_report` | `submitReport()` 성공 시 | `reason`, `word` |

> ⚠️ **Firebase 콘솔 → 프로젝트 설정 → 통합 → Google Analytics 를 사용 설정해야 실제로 수집됩니다.**
> 미설정 상태에서는 코드가 조용히 비활성으로 동작합니다(오류 없음).

### 1-2. `index.html` — 주제 태그 커버리지 수정

**기초 단어 146개가 어떤 주제로도 도달할 수 없는 상태였습니다.** `TOPIC_TAGS`에 `기초` 매핑이 없어 '전체' 세션에서만 확률적으로 뽑혔습니다.

- `TOPIC_TAGS` / `TOPIC_DESC` / `TOPIC_LABEL` 에 **`기초` = 「기초/생활」** 신설, 주제 선택 모달에 버튼 추가(`#ic-sprout`)
- 누락돼 있던 매핑 보강: `학교_배움`→학술, `사회_기본`·`관계_소통`→사회, `감정_기분`→감정
- 결과: 주제로 도달 가능한 단어 **918 → 1,155개**

### 1-3. `index.html` — 웰컴 화면 법적 고지 링크

`#anon-login-btn` 아래에 이용약관·개인정보처리방침 링크 추가. 가입 전 동의 근거 노출은 스토어 심사 요건입니다.

### 1-4. `privacy.html` — Analytics 수집 고지 (필수 동반 변경)

계측을 붙였으므로 방침에 수집 항목·목적·위탁·거부권을 추가하지 않으면 심사 리스크가 됩니다.
