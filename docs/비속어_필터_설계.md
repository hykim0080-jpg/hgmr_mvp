# 오답 통계 패널 — 비속어 필터 설계

> 작성: Cowork · 2026-07-30 · 구현: Code

## 1. 왜 화이트리스트 방식을 버렸나

처음엔 "표시 대상을 정답·유의어·`words.json` 표제어로만 한정하자"고 제안했습니다. **틀린 제안이었습니다.**

현기님 지적대로, `질서`를 **`질사`**로 쓰는 것 같은 **잘못 알고 있는 맞춤법이야말로 이 패널의 핵심 가치**입니다. 화이트리스트는 그걸 전부 「기타」로 지워버립니다. "나만 틀린 게 아니구나"라는 연결감도, 메타인지도 거기서 나옵니다.

그래서 **기능은 그대로 두고 욕설만 거르는** 방향으로 다시 만들었습니다.

---

## 2. 설계 원칙

한국어 비속어 필터의 진짜 위험은 미탐이 아니라 **오탐**입니다. 어휘 학습 앱이 멀쩡한 단어를 가리면 그 자체로 제품이 망가집니다.

1. **오탐 > 미탐.** 애매하면 통과시킨다. 욕설 하나 새는 것보다 정상어 하나 가리는 쪽이 손해가 크다
2. **어휘 사전 우선.** `words.json`의 표제어·유의어(2,102개)에 있는 말은 **무조건 통과**
3. **어간을 두 갈래로 나눈다.** 부분 일치로 검사해도 안전한 것과, 입력 전체가 그것일 때만 검사할 것을 구분
4. **초성체는 입력 전체가 자모일 때만** 검사한다. 정상 답은 절대 그런 형태가 아니다
5. **걸러도 버리지 않는다.** 「기타 N%」로 합산해 비율의 총합을 지킨다

### 어간 분리가 핵심 장치

| 갈래 | 검사 방식 | 예 | 이유 |
|---|---|---|---|
| `STEMS_CONTAIN` | 부분 일치 | 시발 · 병신 · 지랄 · 존나 · 개새끼 | 정상어에 잘 끼어들지 않음 |
| `STEMS_EXACT` | **완전 일치만** | 보지 · 자지 · 후장 · 애미 · 등신 | 부분 일치로 하면 **보지락 · 자지러지다**가 걸림 |

`보지락`(비의 양을 세는 단위), `자지러지다`가 실제로 오탐으로 잡혀서 나눈 구분입니다.

### 우회 대응

정규화 단계에서 처리합니다 — 어간 목록을 부풀리지 않는 쪽이 관리하기 쉽습니다.

| 우회 | 처리 |
|---|---|
| `시 발` `시.발` | 공백·기호 제거 |
| `시1발` | 숫자 제거 |
| `시발발발` | 연속 중복 축약 |
| `시이이발` | 채움 모음(이·으) 뺀 축약형도 함께 검사 |
| `ㅅㅂ` `ㅄ` `ㅗ` | 입력 전체가 자모일 때 초성체 목록 검사 |

## 3. 검증 결과

### 오탐 — 막히면 안 되는 것

| 대상 | 건수 | 오탐 |
|---|---|---|
| `words.json` 표제어 + 유의어 전체 | 2,102 | **0건** ✅ |
| 사전 밖 정상어 · 흔한 맞춤법 실수 | 53 | **0건** ✅ |
| 실제 어휘를 한 글자씩 흐트러뜨린 가짜 오타 | 9,986 | **8건 (0.08%)** |

9,986건 중 걸린 8건은 `후장`·`병신`(실제로 막아야 할 말)과 `종좆`·`풍좆`·`좆목`·`방좇`·`좇속`·`좇소`(사람이 칠 일 없는 무의미한 조합)였습니다. **실사용 영향은 없다고 봅니다.**

어휘 사전 예외를 **끈 상태**에서도 표제어 오탐이 0건이라, 사전 로딩이 실패해도 안전합니다.

### 대표 사례

| 입력 | 판정 | 성격 |
|---|---|---|
| 질사 · 착찹하다 · 뇌졸증 · 설레임 · 역활 | **통과** | 맞춤법 실수 — 이 패널의 핵심 가치 |
| 시발점 · 개나리 · 보지락 · 자지러지다 | **통과** | 정상어 |
| 시발 · fuck | 차단 | 욕설 |
| 시1발 · 시 발 · 시.발 · 시이이발 | 차단 | 우회 표기 |
| ㅅㅂ · ㅄ · ㅗ | 차단 | 초성·기호체 |

## 4. 적용 위치 — 두 곳 모두 권합니다

### ① 표시 단계 (필수)

`buildStatsHtml()` — `index.html:4511` 부근. 상위 5개를 고르기 **전에** 거릅니다.

**이쪽이 필수인 이유가 둘입니다.**

- `firestore.rules`의 `word_stats` 쓰기 규칙은 로그인한 누구에게나 `answers`/`total` 갱신을 허용합니다. 클라이언트를 우회해 직접 쓰면 기록 단계 필터는 소용이 없습니다. **표시 단계만이 확실한 방어선입니다**
- 이미 Firestore에 쌓인 데이터도 소급해서 가려집니다

### ② 기록 단계 (권장)

`recordWordStat()` — `index.html:3771` 부근. 걸린 답은 키로 남기지 않되 **`total`은 그대로 증가**시킵니다. 저장소가 깨끗해지고, 비율 계산도 어긋나지 않습니다.

### 「기타」 행 계산

```
기타 비율 = (total − 화면에 표시한 답들의 합) / total
```

0%면 행을 그리지 않습니다. 걸러진 답이 있을 때만 한 줄 늘어납니다.
