## 0. 이 문서의 전제 — **저작권이 아니라 품질을 기준으로 만듭니다**

자동 생성을 하는 이유가 「기사 예문을 지우기 위해서」가 되면 방향이 틀립니다. 기사 문장은 **애초에 좋은 문항이 아니기** 때문에 바꾸는 것입니다.

| 기사 예문의 문제 | 왜 |
|---|---|
| **금방 낡습니다** | 「코로나 19」·「2020 카트라이더 리그」·「2012 회계연도」 |
| **맥락을 떼면 뜻이 안 통합니다** | *"전체 TV 패널 수요량의 10퍼센트 이상을 받고 있는 것으로 알려졌다"* — 주어가 없습니다 |
| **브랜드 톤과 어긋납니다** | 우리 예문은 문학적·논설적인데 보도자료체가 섞여 있습니다 |
| 저작권 | 위 셋을 고치면 **따라서 해결됩니다** |

**품질 기준으로 갈아 끼우면 저작권은 따라옵니다.** 순서를 뒤집지 마세요.

## 2. 생성 프롬프트

> 그대로 복사해 쓰실 수 있게 완성형으로 썼습니다. `{단어}`·`{뜻}`·`{레벨}`·`{태그}`만 채우면 됩니다.

```
너는 한국어 어휘 학습 앱의 문항 작성자다. 성인·청소년이 대상이며, 이미 한글은 뗐고
어휘력을 기르려는 사람들이다. 유아용이 아니다.

다음 단어에 대한 빈칸 채우기 예문을 만들어라.

  표제어: {단어}
  뜻:     {뜻}
  레벨:   {레벨}
  주제:   {태그}

## 반드시 지킬 것 (하나라도 어기면 폐기된다)

1. 빈칸은 밑줄 4개 `____` 로 정확히 한 번만 쓴다.
2. **표제어를 문장에 쓰지 마라.** 표제어의 일부 글자가 다른 낱말로 들어가는 것도 피하라.
   (예: 표제어가 「개막」이면 "막이 오르다"도 쓰지 마라 — 답이 새어 나간다)
3. **인정 유의어도 문장에 쓰지 마라.** 아래 유의어 목록을 함께 준다: {accepts}
4. **고유명사를 쓰지 마라.** 기업·인물·브랜드·상품·작품·기관·지역 축제 이름 전부.
   - 허용: 세종·뉴턴 같은 **역사 인물**, 「서울」 같은 일반 지명, AI·5G 같은 보통명사화된 약어
   - 금지: 지금 살아 있는 기업/인물/브랜드, 특정 대회·행사·제품 이름
5. **연도·구체적 금액·통계 수치를 쓰지 마라.** (「2012년」·「4500억엔」·「1.4%」)
   숫자가 필요하면 「사흘」·「열 명」·「석 달」처럼 한글로 풀어 쓰고, 사실이 아니라
   상황 묘사에 쓴다.
6. **기사 문체를 쓰지 마라.** 다음 표현은 금지:
   "~로 알려졌다" "~라고 밝혔다" "~고 전했다" "~할 전망이다" "~할 방침이다"
   "~에 나선다" "~것으로 나타났다" "회사 측은" "업계에 따르면" "~에 따르면"
7. ⚠️ **기억하고 있는 실제 기사·백과사전·교과서 문장을 그대로 쓰거나 살짝 고쳐 쓰지 마라.**
   **상황을 새로 지어내라.** 고유명사만 바꾼 문장은 원문을 옮긴 것과 같다.
8. 빈칸 바로 뒤 조사는 아래 규칙을 지켜라. **표제어와 유의어 전부에 맞아야 한다.**
   - 받침 있는 말에만: 이 / 을 / 은 / 과
   - 받침 없는 말에만: 가 / 를 / 는 / 와
   - 「로」는 받침 없거나 ㄹ받침, 「으로」는 ㄹ 아닌 받침
   - **표제어와 유의어의 받침이 서로 다르면 위 조사를 쓰지 마라.**
     대신 「에」·「에서」·「도」·「만」·「까지」·「부터」를 쓰거나, 「____하다/되다」 결합,
     또는 조사 없이 명사를 이어 붙여라 (「____ 공급이 끊기다」)
9. 표제어가 「-하다/-되다/-다」로 끝나는 용언이면 어간만 빈칸으로 두고 어미는 문장에 남겨라.
   (「어긋나다」 → "약속 시간이 서로 ____ 바람에")

## 좋은 문항의 조건

- **그 단어가 잘 맞는 문장**이어야 한다. 다른 말이 들어가도 말은 되지만, 이 단어가
  가장 자연스러운 자리여야 한다. **유일할 필요는 없다.**
- **문장만 읽고도 상황이 그려져야 한다.** 앞뒤 맥락 없이 홀로 서야 한다.
- **25~65자**를 지켜라. 너무 짧으면 단서가 없고 길면 읽다 지친다.
- 어른이 읽는 문장이다. 담백하되 밋밋하지 않게. 필요하면 문어체·논설조도 좋다.
- 시간이 지나도 낡지 않는 소재를 골라라. 계절·일·관계·자연·읽기·일터처럼 오래 가는 것.

## 출력 형식

CSV 한 줄만 출력한다. 설명·머리말을 붙이지 마라.

target,accepts,meaning,sentence,level,tags,ending

- accepts: 큰따옴표 안에 쉼표 구분. **공백 없는 한글만.** (「자본 확충」 ✗ → 「증자」 ✓)
- meaning: 10~35자. **뜻풀이에도 표제어를 쓰지 마라.**
- tags: 아래 목록에서만 고른다 — {ALLOWED_TAGS}
- ending: 용언이 아니면 비워 둔다
```

### 프롬프트에서 특히 중요한 세 줄

| # | 이유 |
|---|---|
| **7번 (원문 회상 금지)** | 생성 모델은 학습한 기사 문장을 그대로 뱉을 수 있습니다. **저작권 문제를 입구에서 막는 유일한 장치**입니다 |
| **8번 (조사 규칙)** | 안 지키면 `check_words.js --fix`가 **유의어를 조용히 지웁니다** (4절) |
| **5번 (수치 금지)** | 기사 발췌를 가려내는 가장 강한 신호였습니다. 생성물에도 같은 기준을 적용해야 나중에 구별이 됩니다 |

## 3. 기존 데이터의 실측값 — 생성물을 여기 맞추세요

프롬프트의 숫자는 임의로 정한 게 아니라 현재 1,388문항을 잰 것입니다.

| 항목 | 실측 |
|---|---|
| 예문 길이 | **중앙 36자** · 10~90% 구간 **25~64자** · 최대 92 |
| 뜻풀이 길이 | **중앙 22자** · 10~90% 구간 10~37자 |
| `accepts` 개수 | **중앙 2개** (1개 651 · 2개 468 · 3개 207) |
| level 분포 | 1: 768 · 2: 453 · 3: **167** |
| `ending` 보유 | **6건뿐** — 값은 「는」 5, 「면」 1 |
| 빈칸 뒤 조사 | **검사 대상 아님 806건(58%)** · 을 196 · 이 96 · 를 90 · 은 50 · 가 50 |

**두 가지가 눈에 띕니다.**

- **58%가 이미 「검사 대상이 아닌」 조사를 씁니다.** 「에」·「도」·「하다」 결합 등. 생성기도 이 비율을 유지하면 조사 사고가 확 줄어듭니다
- **레벨 3이 167개로 얇습니다.** 자동 생성은 **레벨 3을 우선**으로 돌리는 편이 낫습니다 — 상위 티어 콘텐츠 부족은 이미 지적된 문제입니다

## 4. 사전검증 — `add_words.js` 앞에 한 단계 더

`add_words.js`와 `check_words.js`가 이미 튼튼하지만, **생성물에는 그 둘이 안 잡는 실패 유형**이 있습니다.

| 유형 | 기존 검증 | 왜 필요한가 |
|---|---|---|
| **목표어·유의어 노출** | ❌ 없음 | 답이 새어 나갑니다. P39 위반이고 **문항이 무의미**해집니다 |
| **고유명사 잔존** | ❌ 없음 | 자동 생성의 존재 이유가 사라집니다 |
| **기사 문체** | ❌ 없음 | 모델이 학습한 문장을 되뱉은 신호일 수 있습니다 |
| **`accepts` 공백/비한글** | ⚠️ 경고만 (비차단) | 현재 데이터에 이미 7건 있습니다 (「경제적 어려움」·「주요 주주」·「자본 확충」…) |
| **조사 불일치** | ⚠️ `--fix`가 **유의어를 삭제** | 아래 |
| 길이 이상 | ❌ 없음 | 5자짜리·200자짜리가 섞여 들어옵니다 |

### ⚠️ 가장 조심할 것 — `--fix`가 유의어를 조용히 지웁니다

`check_words.js --fix`는 조사와 안 맞는 `accepts`를 **자동으로 제거**합니다. 차단 오류가 아니라 「정리」로 처리되므로 **눈치채지 못한 채 유의어가 사라집니다.**

```
생성물:  sentence = "... 비용 ____을 위해 ..."   accepts = ["감소","절감","축소","감축"]
--fix 후: accepts = ["감소","절감","감축"]        ← 축소(무받침)가 삭제됨
```

**문항은 통과하지만 품질은 조용히 깎입니다.** 사전검증에서 **차단**해야 합니다.

### 사전검증 스크립트

`docs/precheck_generated.py` 로 함께 넣어 두었습니다. CSV를 받아 위 항목을 검사하고 **한 줄이라도 걸리면 0이 아닌 코드로 종료**합니다.

```bash
python3 docs/precheck_generated.py 생성물.csv        # 검사만
python3 docs/precheck_generated.py 생성물.csv --pass 통과분.csv   # 통과분만 추려 저장
```

→ `--pass`로 추린 CSV를 `npm run add-words -- 통과분.csv --dry` 에 넣으면 됩니다.
반려된 줄은 사유와 함께 출력되니 **그 사유 분포가 곧 프롬프트 수정 지침**이 됩니다 (7절).

### 실전 검증 — 기존 1,388문항에 돌려 봤습니다

새 문항용으로 만들었지만 **기존 데이터에 먼저 돌려서 오탐률을 쟀습니다.**

```
통과 1,229 / 1,388  ·  반려 159  ·  확인 요망 1
```

반려 159건의 대부분은 **길이 기준**(권장 25~65자 밖)과 **태그 허용목록**이라 실제 결함이 아닙니다. 그러나 **답이 새어 나가는 결함 7건**이 나왔습니다 — 별도 요청으로 Code에 넘겼습니다.

| 문항 | 문제 |
|---|---|
| **이행** | `accepts`에 「수행」인데 문장이 *"…약속과 ____을 성실히 **수행**해야 합니다"* |
| **효용** | `accepts`에 「활용」인데 문장이 *"…여러 산업에서 **활용**된다"* |
| **수심** | `accepts`에 「걱정」인데 문장이 *"사업 **걱정**에 아버지는…"* |
| **방황·주관·가급적** | **뜻풀이가 답을 그대로 알려줍니다** (*"…이리저리 **방황**하고 헤맴"*) |
| **등가** | `accepts` 「상대」가 「일반 **상대**성 이론」에 걸림 — 유의어 적절성 자체도 의문 |

> **기존 데이터에도 이런 게 남아 있었다는 뜻입니다.** 자동 생성 문항만이 아니라 **전체에 주기적으로 돌릴 가치**가 있습니다.

**한국어 특유의 오탐 처리**: 「원인과 결과」가 목표어 「인과」로 걸리는 문제가 있어, **앞 글자가 한글이면 「확인 요망」으로 낮추고 반려하지 않습니다.** 뒤에 붙는 조사·어미는 한국어에서 정상이라 판정에 쓰지 않습니다.

## 5. 사람 검수 체크리스트

기계가 못 잡는 것만 남겼습니다. **한 문항에 20초** 정도면 됩니다.

### 반드시 (하나라도 아니면 반려)

- [ ] **빈칸에 그 단어를 넣었을 때 자연스러운가?** 뜻은 맞는데 어색한 자리인 경우가 흔합니다
- [ ] **문장만 읽고 상황이 그려지는가?** 주어가 없거나 앞 문장이 있어야 이해되면 반려
- [ ] **유의어를 넣어도 말이 되는가?** `accepts`에 넣은 것들을 실제로 대입해 보세요.
      안 되는 게 있으면 `accepts`에서 빼거나 문장을 고칩니다
- [ ] **뜻풀이가 답을 알려주지 않는가?** 뜻풀이만 보고 답이 나오면 문항이 아니라 사전입니다

### 가급적 (모이면 반려)

- [ ] 어른이 읽을 문장인가? 유아용 예문투(「~했어요」·「참 좋아요」)가 아닌가
- [ ] 시간이 지나도 낡지 않는 소재인가?
- [ ] 앞서 통과시킨 문항들과 **소재가 겹치지 않는가?** 자동 생성은 비슷한 상황을 반복하는 버릇이 있습니다 — **10개쯤 모아서 나란히 보면 잘 보입니다**
- [ ] 레벨이 맞는가? Lv3인데 초등학생도 아는 단어가 아닌가

> **검수는 문항 단위가 아니라 묶음 단위로 하세요.** 한 개씩 보면 다 괜찮아 보이는데, 열 개를 나란히 놓으면 *"또 회사 이야기네"*가 보입니다.

## 6. 소재 다양성 — 생성기가 가장 자주 실패하는 곳

같은 프롬프트로 100개를 뽑으면 **회사·회의·계약 이야기가 절반**을 넘습니다. 기존 데이터가 이미 경제·비즈니스에 치우쳐 있어 더 굳어집니다.

**소재를 프롬프트에서 지정해 돌리세요.**

```
소재: {아래에서 하나를 무작위로}
  계절과 날씨 · 가족과 이웃 · 읽기와 글쓰기 · 배움과 학교 · 일터 · 돈과 살림
  · 여행과 길 · 몸과 건강 · 감정과 관계 · 역사와 옛일 · 자연과 생물
  · 예술과 공연 · 제도와 법 · 과학과 기술 · 운동과 놀이
```

**한 단어에 여러 소재로 서너 개를 뽑아 그중 가장 좋은 하나를 고르는 방식**을 권합니다. 생성 비용은 몇 배지만 검수 반려율이 크게 떨어집니다.

## 7. 돌려서 고치는 방법

**한 번에 완벽한 프롬프트를 만들려 하지 마세요.** 반려 사유를 세서 프롬프트를 고치는 게 빠릅니다.

```
1. 30개 생성  →  사전검증  →  사람 검수
2. 반려 사유를 센다
3. 가장 많은 사유 하나만 프롬프트에 반영한다
4. 다시 30개
```

| 반려 사유가 많다면 | 프롬프트에서 손볼 곳 |
|---|---|
| 목표어·유의어 노출 | 2·3번 규칙에 **구체적 예시**를 추가 |
| 조사 불일치 | 8번에 「받침이 섞이면 무조건 「에」를 써라」로 강하게 |
| 소재 편중 | 6절 소재 지정을 도입 |
| 문장이 홀로 못 섬 | 「앞뒤 맥락 없이 이해되어야 한다」를 맨 앞으로 |
| 어색한 자리 | 뜻풀이 대신 **기존 좋은 예문 2~3개를 예시로** 함께 준다 |

마지막 항목이 가장 효과가 큽니다 — **설명보다 예시가 강합니다.**

## 8. 열어둔 질문

1. **어떤 단어부터 만들 것인가** — 저는 **① 레벨 3 보강 ② 기존 기사 예문 교체분** 순을 권합니다. 레벨 3은 167개뿐이고, 어휘 측정의 상한도 여기 걸려 있습니다
2. **한 번에 몇 개씩** — 30개 단위를 권합니다. 검수 묶음 크기로도 적당합니다
3. **기존 문항 교체인가 신규 추가인가** — 교체는 `words.json` 갱신, 추가는 `add_words.js`라 경로가 다릅니다
4. **`accepts`도 생성할 것인가** — 저는 **생성기가 후보를 내고 사람이 고르는 쪽**을 권합니다. 유의어 판정은 뉘앙스 문제라 자동화가 가장 위험한 자리입니다
