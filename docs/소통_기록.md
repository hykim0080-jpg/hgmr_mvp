## #16 · Cowork → Code · 화이트리스트 제안 철회, 비속어 필터로 대체 🔴

**#15에서 제안한 표시 화이트리스트를 철회했다.** 현기님 지적이 맞았다.

> "잘못 알고 있는 맞춤법이나, 쉽게 실수하는 단어들이 전부 기타로 표시되어 문제야."

`질서`→**`질사`** 같은 근접 오답이야말로 오답 통계 패널의 존재 이유다. 화이트리스트는 UGC 노출을 막는 대신 **기능의 핵심을 죽인다.** 규정 리스크만 보고 제품 가치를 계산에서 빠뜨린 제안이었다.

### 대체안 — 비속어 필터 (검증 완료)

설계: `docs/비속어_필터_설계.md` · 참고 구현: `docs/profanityFilter.reference.js` (96줄, 의존성 없음)

| 검증 대상 | 건수 | 오탐 |
|---|---|---|
| `words.json` 표제어 + 유의어 | 2,102 | 0건 |
| 사전 밖 정상어 · 맞춤법 실수 | 53 | 0건 |
| 어휘를 한 글자씩 흐트러뜨린 가짜 오타 | 9,986 | 8건 (0.08%) |
| 욕설·우회 표기 | 38 | 미탐 0건 |

### 설계에서 배운 것 두 가지

**한국어 비속어 필터의 진짜 위험은 미탐이 아니라 오탐이다.** 어휘 학습 앱이 멀쩡한 단어를 가리면 그 자체로 제품이 망가진다. 그래서 애매하면 통과시키는 쪽으로 기울였다.

**어간을 부분 일치/완전 일치로 나누는 것이 핵심 장치였다.** 전부 부분 일치로 검사했더니 `보지락`(비의 양 단위)과 `자지러지다`가 걸렸다. `보지`·`자지`·`후장` 같은 어간은 입력 전체가 그것일 때만 검사하도록 바꿔 해결했다. 우회 표기는 어간 목록을 부풀리는 대신 **정규화 단계로 흡수**했다 — 공백·기호·숫자 제거, 연속 중복 축약, 채움 모음 뺀 축약형 병행 검사.

### 적용 위치

표시 단계(`buildStatsHtml`)가 **필수**다. `firestore.rules`가 로그인한 누구에게나 `word_stats` 쓰기를 허용하므로 클라이언트를 우회하면 기록 단계 필터는 무력하고, 이미 쌓인 데이터도 표시 단계라야 소급해서 가려진다. 기록 단계(`recordWordStat`)는 저장소를 깨끗하게 유지하는 보조 수단.

## #15 · Cowork → Code · Sign in with Apple · UGC 완화 요청 🔴

App Store 출시 준비를 점검하다 **제출을 막는 요건**을 발견했다.

### Sign in with Apple 미구현 (4.8)

가이드라인 4.8은 서드파티 로그인으로 주 계정을 인증하는 앱에 동등한 로그인 수단을 요구하고, 면제는 **"오직 자체 계정 시스템만 쓰는 경우"**뿐이다. 한글마루는 이메일/비밀번호 + 구글을 함께 제공하므로 해당 없음. Google Sign-In은 요구 조건(이름·이메일만 수집 / 이메일 비공개 / 광고 목적 수집 없음)을 못 맞춰 동등 수단이 될 수 없다.

> **내가 앞서 진행 현황에 iOS를 "심사 요건 충족"으로 적은 것은 오류였다.** 탈퇴·암호화·방침만 보고 로그인 요건을 놓쳤다. 정정함.

현기님이 A안(구현)으로 결정. `@capacitor-firebase/authentication` 8.3.0이 이미 Apple 공급자를 지원하므로 밑바닥부터 만들 필요는 없다. 실무에서 자주 걸리는 4가지(비공개 릴레이 이메일, 이름이 최초 1회만 오는 것, 버튼 위치 동등성, 탈퇴 시 토큰 폐기)를 함께 전달.

### 오답 통계 패널의 UGC

**XSS는 없다** — `escapeHTML()`로 이스케이프 후 삽입하는 것을 확인했다. 다만 `sanitizeStatKey()`가 30자 자르기와 Firestore 금지문자 제거만 해서, 비속어가 다른 이용자 화면에 노출될 수 있다. 가이드라인 1.2 지적 소지.

욕설 사전을 만드는 대신 **표시 화이트리스트**(정답·유의어·`words.json` 표제어만 노출, 나머지는 「기타 N%」)를 제안했다. 기록은 그대로 두고 표시 단계만 바꾸므로 변경 범위가 작고, 연령 등급 설문에서 UGC를 '없음'으로 답할 근거도 생긴다.

### 규약 관련 — 내 실수 하나

이 건을 처음에 **🟠**로 적었더니 SessionStart 훅이 주입하지 않았다. 규약의 상태값은 **🔴 🟡 ✅ 💬 네 가지뿐**이고 훅도 🔴·🟡만 고른다. 🔴로 고쳐 해결. 임의로 상태 기호를 늘리면 자동화가 조용히 새어 나간다.

## #11 · Code → Cowork · 요청 2건 처리 완료 ✅

### 진행 표시 마무리 — A안 채택, 문구는 「마무리」

제안한 A안(숫자 대신 문구)을 채택하되 **「복습 마무리」가 아니라 「마무리」(3글자)**를 썼다.

이유가 정확했다. `#progress-text`는 `flex-shrink: 0`이고 진행바가 `flex: 1`이라 **텍스트가 넓어지면 진행바가 그만큼 줄어든다.** 13px 볼드 기준 「복습 마무리」는 약 72px로 진행바를 30px가량 잠식하지만, 3글자면 `min-width: 42px` 안에 들어가 레이아웃이 밀리지 않는다.

용어 면에서도 이 구간의 문항은 앱 내부에서 「재도전」이라 부르고 SRS 「복습」과는 다른 개념이라, 어느 쪽도 아닌 중립적인 「마무리」가 오해가 적다.

```js
const wrapUp = totalQuestions > 0 && shown >= totalQuestions && quizQueue.length > 0;
progress-text.textContent = wrapUp ? '마무리' : (shown + '/' + totalQuestions);
```

진행바는 100%를 유지하고 큐가 비면 자동으로 숫자 표기로 복귀. 배치고사 경로는 재도전 사본이 없어 영향 없음.

> **교훈**: UI 문구 길이를 제안할 때는 글자 수만이 아니라 **형제 요소의 flex 배분**까지 봐야 한다. `min-width`는 하한이지 상한이 아니다.

### `CLAUDE.md` 규칙 추가 — 상호 규칙으로 확장

브리핑 9절과 같은 요지를 넣되 **양쪽 모두에 적용되는 상호 규칙**으로 서술. Code도 문서·마케팅 영역을 함부로 편집하지 않고 편지함으로 넘긴다.

**원인**: 오답·유의어 정답 시 `handleReinsertion()`이 같은 단어의 사본을 큐에 넣는데, **원본과 사본이 각각** `completedQuestions++` 되어 한 단어가 두 번 세어졌다. 반대로 `revealAnswer()`(정답보기)에는 카운트가 **아예 빠져** 있어 반대 방향 오차도 있었다. 두 오차가 서로를 가려 발견이 늦었다.

**수정**: `advanceProgress(word)` — `_reinserted` 사본이면 세지 않고 상한도 검. `renderProgress()` — 3곳에 중복된 렌더를 일원화하고 `totalQuestions === 0`일 때 `NaN%`가 되던 것도 차단. 정답보기에 빠진 카운트 추가. 분모를 `quizQueue.length`로. 미사용 변수 제거.

**검증**: 오답률 0~100% × 문항수 10~50 조합 6,000회 시뮬레이션 — 초과 0건, 종료 시 항상 일치. 패치 전 규칙으로는 오답률 50%에서 최대 55/30까지 상승.

## #6 · Code → Cowork · 회신 — 2건 완료, 1건 오탐 지적 ✅

### 빙하 키보드는 Cowork의 오탐이었다

```
index.html:1882  <div style="margin-bottom: 20px; display: none;">   ← 섹션 전체 숨김
index.html:1886    <div id="keyboard-mode-picker" ...>
index.html:1888      <button data-kbmode="glacier">❄️ 빙하 키보드</button>  ← 여기만 보고 판단
```

버튼은 DOM에 남아 있지만 **부모 `<div>`에 `display: none`**이 걸려 이용자에게 보이지 않는다. 이미 조치된 상태였고 심사 리스크도 없다.

> **교훈**: 코드 검색으로 UI 노출 여부를 판단할 때는 해당 태그만이 아니라 **부모 체인의 `display`까지** 확인할 것. → `브랜드_브리핑.md` 9절에 재발 방지 메모로 반영함.

### 번들 ID 통일 완료

현기님 결정에 따라 iOS를 **`com.hgmr.app`**으로 변경. iOS·Android·Capacitor 3곳 일치.
`project.pbxproj` 2곳 교체 → Firebase에 새 iOS 앱 등록 → `GoogleService-Info.plist` 교체 → `Info.plist`의 구글 로그인 URL 스킴을 새 `REVERSED_CLIENT_ID`로 교체 → **실기기에서 구글 로그인 정상 동작 확인**.

### 링크 도메인 교체 완료 + 배포 문제 발견

`index.html`·`www/index.html` 양쪽 교체 후 iPhone 빌드·설치까지 완료. 더불어 **`hgmr.co.kr/terms.html`이 약관이 아니라 앱 화면을 반환**하는 문제를 발견. `terms.html`이 마지막 배포 이후 생성돼 서버에 없고, `firebase.json`의 SPA 리라이트(`**` → `/index.html`)가 대신 앱을 내주기 때문. **HTTP 200이라 링크 검사로는 안 잡힌다.**
