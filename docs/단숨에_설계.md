### ✅ 2026-08-05 확정 — 원칙과 충돌하지 않습니다

v1의 4번은 **「틀려도 감점 없음」**이었는데, 시간 페널티는 **명백히 벌입니다.**

제가 정리한 해석은 이렇습니다 — **어휘 고도는 여전히 안 내려가고, 벌은 그 판의 기록 안에서만 일어난다.** 즉 원칙의 정확한 문장은 *"어떤 불이익도 주지 않는다"*가 아니라 **"틀려도 어휘 고도는 내려가지 않는다"**입니다.

**현기님이 이 해석을 확정하셨습니다** — *"복습 시스템은 메인 학습과 별개의 미니게임 형식"*. 원칙의 정확한 문장은 **"틀려도 어휘 고도는 내려가지 않는다"**이고, 미니게임 안의 페널티는 여기 걸리지 않습니다.

## 2. 이름 — 「단숨에」

`타임어택`은 영어 차용어라 브랜드 목소리와 어긋나고, **이름부터 시간에 쫓기는 인상**을 줍니다.

**「단숨에」**는 등반 은유와 붙고(*한 호흡에 오르는 한 구간*), 속도가 아니라 **기세**를 가리킵니다. 하랑이가 말하기도 좋습니다 — *"단숨에 열 개, 해볼까?"*

> 최종 결정은 현기님 몫입니다. 코드에서는 **문구를 한 곳에 모아두면** 나중에 바꾸기 쉽습니다.

## 3. 규칙

### 판의 구성

**10문제 고정.** 다 풀면 끝나고, **걸린 시간이 기록**입니다.

```
기록 = 실제 경과 시간 + (포기한 문항 수 × 페널티)
```

10문제인 이유: 프로필 설정의 **「1회 학습 단어 수」에 이미 10이 있어** 사용자가 아는 단위이고, 한 판이 1~2분이라 **부담 없이 다시 하기** 좋은 길이입니다.

### 대상 단어

**`learnedEntry(t).m === true` 인 단어** — **학습 어휘**(첫 시도 정답을 맞힌 적이 있는 단어, 낱말카드에 들어 있는 것)만.

- 「1회 이상 학습」의 기준을 `m`으로 잡는 이유: 앱 전체(초록 조각·낱말카드·업적)가 이미 이 기준을 씁니다. **새 기준을 만들면 숫자가 어긋납니다**
- 뽑는 순서: **복습 기한이 도래한 것 우선**(`isDueForReview`), 그다음 오래된 순
- **오답 이력이 많은 단어를 앞에 몰지 마세요.** 여기서는 *기분 좋게 꺼내는 경험*이 목적이라 초반에 꺾이면 판이 끝납니다

### 열리는 조건

**학습 어휘 30개 미만이면 모드 자체를 숨깁니다.**

- 한 판이 10문제라 풀이 20개면 두 판 만에 전부 봅니다. **30개가 최소선**입니다
- 잠금 아이콘·자물쇠 연출 금지. **그냥 안 보이게** 하고, 30개를 넘긴 날 결과 화면에서 *"단숨에가 열렸어"* 한 줄로 알립니다

### 문항당 기회 3번

| 시도 | 결과 |
|---|---|
| 1·2회 오답 | 입력창만 비우고 **같은 문제에 머무름**. 남은 기회 표시가 하나 줄어듦 |
| 3회 오답 | **페널티 + 정답을 잠깐 보여주고 → 다음 문제.** 정답으로 세지 않음 |
| 「다음 문제」 버튼 | 남은 기회와 무관하게 **즉시** 위와 동일 처리 |

- 오답 처리는 기존 `_synRetry` 분기의 **자리 대기 방식**을 재사용하면 됩니다
- **하랑이 눈물 포즈를 쓰지 마세요.** 오답 모션 없음
- 남은 기회는 **점 3개(● ● ○)**로. **하트 모양 금지** — 생명 시스템으로 읽힙니다

### 시간 페널티

**+10초**를 제안합니다.

한 문항이 평균 6~8초라면 10초는 *한 문제 반*어치입니다. 너무 작으면 넘기는 게 이득이고, 너무 크면 초반 실수 하나로 판이 무의미해집니다. **첫 배포 후 분포를 보고 조정할 값**입니다.

- 표시는 **조용히**. 「+10초」를 붉게 번쩍이거나 소리를 내지 않습니다
- 시계 숫자를 크게 띄우지 마세요. 진행 중에는 **몇 번째 문제인지(3/10)**만 보이고, **경과 시간은 결과에서** 봅니다

> **왜 시계를 숨기는가** — 초 단위 숫자가 올라가는 걸 보면서 푸는 건 문항별 타이머와 다를 게 없습니다. *"총 시간만 잰다"*는 결정의 의미는 **한 문제에서 뜸 들일 자유**인데, 시계가 보이면 그 자유가 사라집니다.

### 넘어갈 때 정답을 보여줍니다 — **시계는 멈춘 채로**

포기한 문항의 정답을 **0.8초** 보여주고 넘어갑니다. 복습 모드라 정답 노출이 값집니다.

**그 0.8초 동안 시계를 멈추세요.** 안 그러면 정답을 보여주는 시간까지 기록에 들어가 이중 페널티가 됩니다.

### 그 밖

- **정답 보기 버튼 없음** (「다음 문제」가 그 역할을 겸함)
- 초성 상시 표시(`ㄱㄹ`) — 아래 7절 참고
- 중간에 ✕로 나가면 기록을 남기지 않습니다

## 4. 기록과 보상

### 기록

**걸린 시간.** 짧을수록 좋습니다. 남기는 것은 **최단 기록 하나**뿐이고 순위표는 없습니다.

결과에는 **시간이 주인공**이고 맞힌 개수는 곁들이입니다 — 포기한 문항은 이미 페널티로 시간에 반영돼 있어 **두 번 세는 셈**이라 크게 띄울 이유가 없습니다.

### 재화 — 파란 조각만 씁니다

**새 재화를 만들지 마세요.** 파란 조각은 아직 소비처도 없는데 여기서 하나 더 늘면 둘 다 의미를 잃습니다.

| | 규칙 |
|---|---|
| 지급 | **하루 첫 판에만** 맞힌 개수만큼 파란 조각 (최대 10) **+ EXP** |
| 이후 판 | 조각 없음. **기록 도전만** |
| 보너스 | 3연속 보너스·완주 보상 **없음** |

**파밍 방지가 목적입니다.** 단숨에가 일반 학습보다 조각 수익률이 높으면 사용자는 새 단어를 배우지 않고 이것만 돌립니다. 게임 층이 학습을 잡아먹는 전형적인 실패입니다.

「하루 첫 판만」은 그걸 막으면서도 **잠그지 않습니다.** 두 번째 판부터는 조각이 안 나오니 동기가 자연히 기록 도전으로 옮겨가고, 그건 **하고 싶은 사람만 하는 일**이 됩니다. 횟수 제한·쿨다운 같은 벌 장치가 필요 없습니다.

## 5. 절대 건드리지 않는 것 — 이 절이 가장 중요합니다

「어휘 고도와 완전히 분리」는 화면에 고도를 안 띄우는 것만으로 지켜지지 않습니다. **아래를 전부 손대지 말아야** 합니다.

| 건드리지 말 것 | 이유 |
|---|---|
| **`vocabRating` · `vocabPeak` · `ratingHistory`** | 고도가 **타자 속도에 의존**하게 됩니다. Elo 측정의 의미가 무너집니다 |
| **`itemRatingDelta` · `pendingItemDelta`** | `rateAnswer()`가 고도와 **함께** 건드리는 값 — **문항 난이도 전역 보정**입니다. 여기서 부르면 **단어 난이도 라벨 자체가 타자 속도에 오염**됩니다 |
| **`learnedWords`의 SRS 필드** (`s`·`n`·`w`·`c`) | 시간에 쫓겨 못 친 것은 **망각의 증거가 아닙니다.** 여기서 틀렸다고 기억 단계를 0으로 되돌리면 페널티가 **판 밖으로 새어 나갑니다.** 반대로 맞혔다고 단계를 올리면 복습 간격이 실제 기억보다 빨리 벌어집니다 |
| **전역 오답 통계** (`word_stats`) | "남들은 뭐라고 썼을까"는 차분히 생각한 답이라야 값이 있습니다. 속도 압박 하의 오타가 섞이면 이 앱의 고유 자산이 오염됩니다 |
| **`totalCorrectFirstTry` · 평균 정답률** | 속도 압박 하의 입력이 정답률 통계를 왜곡합니다 |

> **⚠️ 2026-08-05 변경 — 스트릭·EXP는 제외 목록에서 빠졌습니다.**
> 현기님 결정(P32): *"복습 학습 및 앞으로 추가되는 학습들로도 오르게 해줘."*
> **스트릭은 「그날 학습했는가」의 기록**이므로 단숨에로도 오르는 게 맞습니다.
> **EXP는 파밍 경로가 되므로 파란 조각과 같은 규칙**(하루 첫 판만 지급)을 적용합니다.
> 나머지(`vocabRating`·SRS·`itemRatingDelta`·전역 오답 통계)는 **여전히 제외**입니다 — P30, 등급 **A**.

**호출하지 말아야 할 함수**: `recordLearned()` · `rateAnswer()` · `raisePeak()` · `pushRatingHistory()` · `flushItemRatings()` · 오답 통계 기록.

그중 **`rateAnswer()`가 가장 위험합니다** — 이름과 달리 고도만 갱신하는 게 아니라 문항 난이도 전역 보정까지 함께 합니다. 레벨 재배정이 검증 불가로 막혀 있는 지금, 난이도 라벨이 한 번 더 오염되면 손쓸 방법이 없습니다.

> **한 줄로: 단숨에는 기존 어떤 지표에도 쓰지 않는 완전한 별도 트랙입니다.** 남기는 것은 자기 기록과 파란 조각뿐입니다.

**학습 효과가 없어지는 것 아니냐** — 아닙니다. 인출 연습의 효과는 기록 여부와 무관하게 뇌에서 일어납니다. 기록하지 않는 것은 *측정을 지키기 위한 선택*이지 학습을 포기하는 게 아닙니다.

## 7. 남은 위험 — 솔직히 적어둡니다

### 기록이 타자 속도에 좌우됩니다 — v1보다 더 직접적입니다

기록이 **곧 시간**이 되면서 타자 속도의 영향이 v1보다 커졌습니다. 앱은 이미 **시스템 키보드**를 쓰고 있어(`usesGlacierKeyboard() → false`) 자모 키보드 문제는 없지만, 주관식인 이상 **입력 시간은 남습니다.**

완화책은 **초성 상시 표시**뿐입니다. 인출에 걸리는 시간을 줄여 상대적으로 타이핑 비중을 낮춥니다.

이건 `docs/브랜드_원칙_점검표.md`의 **충돌 4**와 직결됩니다 — **「직접 타이핑」이 A등급 원칙이면 이 모드의 기록은 태생적으로 불순**하고, B등급이면 이 모드만 다른 형식(예: 초성 조합 선택)을 써도 됩니다. **먼저 정해 주셔야 합니다.**

### 판마다 단어가 달라 기록이 운에 좌우됩니다

`괴리`(2자)와 `자기기만`(4자)은 입력 시간이 두 배 차이입니다. 10문제를 무작위로 뽑으면 **어떤 판은 그냥 쉽습니다.**

- 남과 비교하지 않으므로 공정성 요구는 낮지만, **「최고 기록」이 운 좋은 판일 수 있습니다**
- 완화하려면 **10문제의 총 글자 수를 일정 범위로 맞춰** 뽑는 방법이 있습니다. 구현이 크게 어렵지 않고 효과가 확실합니다 — **Code 판단에 맡깁니다**

### 「아는데 손이 늦어서」라는 좌절

이 앱의 인지 과제는 설단 현상 — *아는데 안 떠오르는 상태*입니다. 시간을 재는 것과는 원래 궁합이 나쁩니다. 제한 시간을 없애고 기회를 3번 준 것이 이걸 크게 눌러주지만 **없앨 수는 없습니다.**

→ 그래서 **일반 학습이 기본이고 단숨에는 곁가지**여야 합니다. 홈에서 학습 시작 버튼보다 **작게, 아래에** 두세요.

## 8. 데이터 스키마

`users/{uid}` 하위에 **한 필드만** 추가합니다.

```js
dansume: {
  bestMs: 88400,          // 최단 기록(ms) — 페널티 포함
  bestDate: "2026-08-01",
  plays: 23,
  lastRewardDate: "2026-08-01"   // 하루 첫 판 판정용
}
```

기존 필드는 **하나도 건드리지 않습니다.** `blueShards`만 예외적으로 증가합니다.

## 9. 계측

```js
track('dansume_start', { learned_words: n });
track('dansume_end', {
  ms: 102400,          // 페널티 포함 최종 기록
  raw_ms: 82400,       // 페널티 제외 실제 경과
  correct: 8,          // 10문제 중 맞힌 수
  gave_up: 2,          // 3회 소진 + 다음 버튼
  is_best: false,
  rewarded: true
});
track('dansume_quit', { at_question: 4 });   // 중도 이탈
```

| 보는 것 | 판단 |
|---|---|
| `dansume_start` 수 / 일반 세션 수 | **0.3을 넘으면 위험** — 학습을 밀어내고 있음 |
| `gave_up` 평균 | **3을 넘으면 페널티나 기회 수를 조정**해야 함 |
| `raw_ms ÷ correct`와 **단어 글자 수**의 상관 | 강하면 **어휘가 아니라 타자를 재는 중** → 형식을 바꾸거나 접기 |
| `dansume_quit` 비율 | 높으면 10문제가 길다는 뜻 |
| 단숨에 이용자의 **일반 세션 유지율** | 이게 안 오르면 리텐션 기여가 없다는 뜻 |

**마지막 지표가 이 모드의 존재 이유입니다.** 재미있기만 하고 일반 학습 복귀를 못 만들면 실패입니다.

## 10. 열어둔 질문

1. **페널티 +10초가 맞는가** — 첫 배포 후 `gave_up`·`ms` 분포를 보고 조정
2. **기회 3번이 맞는가** — 2번이면 판이 빨라지고, 4번이면 늘어집니다
3. **10문제가 맞는가** — `dansume_quit`가 높으면 줄여야 합니다
4. **총 글자 수를 맞춰 뽑을 것인가** (7절 두 번째 위험)
5. **「단숨에」라는 이름**
6. **`docs/브랜드_원칙_점검표.md`의 충돌 2·4** — 이게 정해져야 이 설계가 확정됩니다
