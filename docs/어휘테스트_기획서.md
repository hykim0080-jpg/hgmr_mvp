# 「10초 어휘 테스트」 공유 랜딩 기획서

> 작성: Cowork · 2026-07-30 · 구현: Code
> 목적: **앱 설치 전 유입 장치.** SNS에서 링크 하나로 유입 → 30초 안에 결과 → 공유 → 앱으로

---

## 1. 왜 만드나

지금 한글마루의 문제는 기능이 아니라 **아무도 모른다는 것**입니다. 스토어 등록만으로는 유입이 생기지 않습니다.

이 랜딩은 SNS 콘텐츠(`docs/인스타그램_콘텐츠_초안.md`의 필라 ①·④)의 **착지점**입니다. 게시물을 본 사람이 "나는 몇 점이지?"로 넘어올 곳이 필요합니다.

**핵심 설계 원칙 — 앱 설치를 요구하지 않는다.** 로그인도, 가입도 없습니다. 마찰이 하나라도 있으면 SNS 유입은 그 자리에서 이탈합니다. 앱 유도는 결과를 보여준 **뒤에** 합니다.

---

## 2. 사용자 흐름

```
SNS 게시물 → hgmr.co.kr/test
   ↓  (즉시 시작 — 로딩 화면·로그인·설명 없음)
문항 1~5  (문항당 ~6초, 오답도 그냥 넘어감)
   ↓
결과: 어휘 고도 「해발 N m · 티어명」 + 하랑이
   ↓
[결과 카드 저장] [공유하기] [제대로 측정하기 →]
                                    ↓
                            앱/웹앱 배치고사(20문항)
```

**중요**: 5문항으로 나온 고도는 **어림값**입니다. 결과 화면에 "정확한 측정은 20문항 배치고사로"라고 명시해, 앱으로 넘어갈 이유를 만듭니다. 과장하면 앱에서 재측정했을 때 실망으로 이어집니다.

---

## 3. 문항 — 고정 5문항 (전원 동일)

배치고사처럼 적응형으로 갈 필요가 없습니다. **전원이 같은 문제를 풀어야** "나는 3번에서 막혔는데 너는?"이라는 대화가 생기고, 그게 공유의 동력입니다.

난이도를 계단식으로 배치해 대부분이 3~4번에서 처음 막히도록 했습니다. 첫 문항에서 막히면 바로 이탈합니다.

| # | 단어 | Lv | 문장 | 의도 |
|---|---|---|---|---|
| 1 | **안도** | 1 | 실종되었던 아이가 무사히 돌아왔다는 소식에 부모는 ____의 한숨을 내쉬었다. | 거의 다 맞힘 — "할 만하다"는 첫인상 |
| 2 | **환희** | 2 | 우승이 확정되는 순간 선수들은 서로 얼싸안고 ____의 함성을 질렀다. | 알지만 잘 안 떠오르는 단어 |
| 3 | **착잡하다** | 2 | 정든 회사를 떠나는 마지막 출근길, 시원함과 서운함이 뒤엉켜 마음이 ____. | 첫 고비 · 공감 유발 |
| 4 | **겸양** | 3 | 스스로가 모든 것을 알지 못한다는 사실을 인정하는 ____이야말로 진정한 앎에 도달하는 유일한 열쇠다. | 상위권 분기 |
| 5 | **방증** | 3 | 우리가 무심코 내뱉는 사소한 언어 습관들은 현재 내면의 상태가 얼마나 불안한지를 보여주는 투명한 ____이 된다. | '반증'과 헷갈림 — 최상위 분기 |

- 뜻풀이는 **입력 전에는 숨기고**, 틀렸거나 넘어갔을 때 정답과 함께 보여줍니다. (앱 퀴즈와 다른 점 — 여기선 힌트가 있으면 변별이 안 됩니다)
- 유의어(`accepts`)는 앱과 동일하게 인정합니다
- 재시도 없음. 한 번 입력하면 넘어갑니다 — 30초를 지키기 위해서입니다
- 입력은 **시스템 키보드**로. 앱과 동일

> 문항 데이터는 `words.json`에서 그대로 가져오되, 5개만 담은 별도 상수로 두는 편이 낫습니다. 전체 `words.json`(533KB)을 이 페이지에서 받게 하면 첫 로딩이 무너집니다.

## 4. 결과 화면

### 고도 산출

앱의 `ratingTier()`·`peakAltitude()`를 그대로 쓰되, 5문항이라 **구간을 넓게** 잡습니다.

| 맞힌 수 | 표시 고도 | 티어 |
|---|---|---|
| 0~1 | 해발 120~280 m | 기슭 |
| 2 | 해발 350~480 m | 오르막 |
| 3 | 해발 550~680 m | 중턱 |
| 4 | 해발 780~880 m | 능선 |
| 5 | 해발 950~1,100 m | 마루 |

구간 안에서는 소수의 난이도 가중치로 흩뿌려, 같은 개수를 맞혀도 값이 조금씩 달라지게 합니다. 똑같은 숫자가 타임라인에 반복되면 공유 유인이 떨어집니다.

### 화면 구성

- 산 일러스트 + 내 위치 표시 (앱의 어휘 고도 안내 모달 재사용)
- **해발 N m** — 가장 큰 요소
- 티어명 + 하랑이 한마디 (반말·담백)
  - 마루: "여기까지 올라온 사람 많지 않아. 대단해."
  - 기슭: "여기서부터 시작이야. 같이 올라가자."
- 문항별 정오답 5칸 (어디서 막혔는지 — 대화 소재가 됩니다)
- **"정확한 고도는 20문항 배치고사로 측정할 수 있어요"** + 앱/웹앱 버튼

## 5. 공유

### 결과 카드 (핵심)

캔버스로 **1080×1350 PNG**를 즉석 생성해 저장·공유하게 합니다. 스크린샷을 찍게 하면 상태바·브라우저 UI가 들어가 지저분합니다.

카드에 들어갈 것: 해발 고도 + 티어 + 하랑이 + `한글마루` 워드마크 + `hgmr.co.kr/test`

> 브랜드 자산은 `브랜드_브리핑.md` 4절 (브랜드 그린 `#10B981`, 민트 `#ECFDF5`, Jua 워드마크).
> 방금 만든 `hgmr-screenshot-tool.html`의 캔버스 합성 코드를 참고하시면 빠릅니다.

### 링크 미리보기 (OG 태그)

카카오톡·인스타 DM으로 링크가 돌 때 미리보기가 없으면 클릭률이 크게 떨어집니다.

```html
<meta property="og:title" content="10초 어휘력 테스트 — 나의 어휘 고도는?">
<meta property="og:description" content="5문항으로 재보는 내 어휘력. '심심한 사과'가 왜 사과가 아닌지 아시나요?">
<meta property="og:image" content="https://hgmr.co.kr/og-test.png">   <!-- 1200×630 고정 이미지 -->
<meta property="og:url" content="https://hgmr.co.kr/test">
<meta name="twitter:card" content="summary_large_image">
```

`og:image`는 개인 결과가 아니라 **고정 이미지**여야 합니다. 결과별 동적 OG는 서버가 필요하고, 지금 구조(정적 호스팅)로는 과합니다.

## 6. 기술 메모

- **별도 경량 페이지**로. `index.html`(386KB)에 붙이면 안 됩니다. 목표는 **첫 화면 1초 이내**
- `firebase.json`의 SPA 리라이트(`**` → `/index.html`)에 걸리므로 **`/test` 예외 규칙 필요**. `terms.html`이 앱 화면을 반환하던 것과 같은 함정입니다
- 로그인 없음 → Firestore 쓰기 없음. 익명 통계는 Analytics 이벤트로만
- 앱 이동 버튼: 스토어 등록 전에는 웹앱(`hgmr.co.kr`)으로, 등록 후 스토어 링크 추가

### 계측 (필수)

이 랜딩은 **전환율을 재려고 만드는 것**이라 계측이 없으면 만드는 의미가 없습니다.

| 이벤트 | 파라미터 | 보는 것 |
|---|---|---|
| `test_start` | `referrer` | 유입량 |
| `test_question` | `index`, `correct` | **어디서 이탈하는지** |
| `test_complete` | `score`, `altitude` | 완주율 |
| `test_share` | `method` | 공유율 |
| `test_to_app` | — | **최종 전환** |

`index.html`의 `track()`과 같은 방식으로 붙이면 됩니다.

## 8. 성공 기준

출시 후 2주 관찰.

| 지표 | 최소 | 목표 |
|---|---|---|
| 완주율 (`test_complete` / `test_start`) | 50% | 70% |
| 공유율 (`test_share` / `test_complete`) | 5% | 15% |
| 앱 전환 (`test_to_app` / `test_complete`) | 10% | 25% |

완주율이 50% 아래면 문항이 어렵거나 길다는 뜻입니다 — `test_question`의 이탈 지점을 보고 3~4번을 조정합니다.
