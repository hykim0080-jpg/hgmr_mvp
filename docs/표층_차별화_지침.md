# 표층 차별화 지침 — 같은 기능, 다른 물건

> 작성: Cowork · 2026-08-01
> 근거: `docs/경쟁분석_말해보카.md` v4 (실제 화면 10장)
> 현기님 방침 (2026-08-01): **"벤치마킹한 것 자체를 숨길 생각은 없다. 다만 화면이나 대사에서 무작정 카피했다는 인상을 주지 않으려는 것. 핵심 기능과 편의성은 챙기되 꼭 정확히 똑같은 길을 갈 필요는 없다."**

---

## 1. 입장

**방법론이 겹치는 건 숨기지 않습니다.** 문맥 빈칸 · 주관식 타이핑 · 3단 판정 · SRS · 단계적 힌트 — 좋은 방법이라서 씁니다. 감출 일이 아니고, 감춰지지도 않습니다.

**갈라지는 곳은 표층입니다.** 이름 · 문구 · 색 · 연출 · 순서. 이건 **기능이 아니라 저작**이고, 저작이 닮으면 그때는 변명이 안 됩니다.

> 사용자가 *"어, 말해보카 같은데"*라고 느끼는 건 대개 **기능 목록 때문이 아니라 문장 하나·색 하나** 때문입니다. 거꾸로 말하면 **표층만 확실히 갈라도 인상은 충분히 달라집니다.**

---

## 2. 판단 기준 한 줄

> **관습은 따르고, 저작은 갈라진다.**

어떤 요소를 두고 **"이걸 처음 지어낸 사람이 있나?"**를 물어보면 됩니다.

| | 예 | 처리 |
|---|---|---|
| **관습** — 아무나 그렇게 함 | 진행바가 화면 위, 입력창이 아래, 정답을 초록으로, 빈칸을 회색 박스로 | **따라도 됩니다.** 굳이 다르게 하면 앱만 나빠집니다 |
| **저작** — 누군가 지어냄 | 「길이 보기」라는 이름, *"맞혀 보시겠어요?"*라는 문장, 트로피+별 진행 아이콘, 붉은 오답 화면 | **반드시 갈라집니다** |

**다르게 하려다 나빠지는 곳을 구분하는 게 이 지침의 절반입니다.** 관습을 어기는 건 독창성이 아니라 불편입니다.

### 그리고 두 번째 시험 — **문구를 다 지워도 달라 보이나**

저작을 갈라놓기로 했다면, **문구를 바꾸는 것으로는 안 됩니다.**

두 화면에서 **글자를 전부 지웠다고 상상**해 보세요. 그래도 다르면 진짜 차이(형식·시점·주체)이고, 똑같아 보이면 **말투만 바꾼 것**입니다. 후자는 차별화가 아니라 리스킨이고, **오히려 티 나게 감추는 인상**을 줍니다.

---

## 3. 굳이 갈라지지 말 것

아래는 **닮아도 괜찮습니다.** 여기서 차별화하면 손해입니다.

- 진행바가 상단, 입력창이 하단, 확인 버튼이 오른쪽
- 빈칸을 회색 박스로 표시
- **정답을 초록으로** — 거의 보편 관습입니다
- 문항 하단에 작게 출처 표기
- 뜻풀이 주석을 문장 아래 작은 글씨로
- 3단 판정이라는 **구조 자체**, SRS 간격, 단계적 힌트라는 **발상**
- 「다음 문제」·「정답 보기」 같은 **기능 그대로의 이름**

## 4. 갈라져야 할 것

> **⚠️ 2026-08-02 전면 재작성.** 초판 4절은 *"같은 내용을 말투만 비튼 것"*이라는 현기님 지적을 받았고, **맞는 지적이었습니다.**
> *"clearly도 정답인데…"* → *"그것도 맞는 말이야…"* 는 **같은 말을 반말로 옮긴 것**입니다. 하는 일이 똑같으면 문구를 바꿔도 같은 물건이고, **오히려 티 나게 감추는 인상**을 줍니다.

### 4-0. 시험 — **문구를 다 지워도 달라 보이나**

두 화면을 나란히 놓고 **글자를 전부 지웠다고 상상**해 보세요.

| | |
|---|---|
| 그래도 다르면 | ✅ **진짜 차이** — 형식·시점·주체가 다른 것 |
| 똑같아 보이면 | ❌ **말투만 바꾼 것** — 문구를 아무리 다듬어도 리스킨 |

초판 4절 항목 대부분이 아래쪽이었습니다. 아래는 **위쪽만** 남긴 것입니다.

---

### 4-1. 뿌리에 있는 차이 — **그들은 대화형 앱, 우리는 문장 중심 앱**

말해보카의 화면은 전부 **채팅**입니다 🔍. 말풍선이 위에서 내려오고, 캐릭터가 말을 걸고, 피드백도 말풍선이고, 격려도 말풍선입니다. **모든 정보가 「누군가 나에게 하는 말」로 전달됩니다.**

**우리가 말풍선으로 같은 정보를 주면, 반말이든 존댓말이든 같은 물건입니다.**

한글마루는 **문장이 화면의 주인공**인 앱입니다. 예문이 문학적이고, 사용자가 보러 오는 것도 문장입니다. 그러면 피드백도 **문장 안에서 일어나야** 합니다.

> **원칙: 설명하지 말고 보여준다. 말풍선을 줄이고 문장이 반응하게 한다.**

이 하나가 아래 항목 대부분을 낳습니다. 그리고 이건 **글자를 지워도 다릅니다** — 한쪽은 말풍선이 쌓인 채팅 화면이고, 한쪽은 문장 한 덩이가 놓인 화면입니다.

---

### 4-2. 유의어·뉘앙스 — **설명문 대신 「대조 예문」**

| | |
|---|---|
| 말해보카 🔍 | 말풍선으로 **설명한다** — *"put ~ away는 다 쓴 물건을 '치운다'는 거예요"* (사전 뜻풀이 한 줄) |
| 한글마루 | **그 단어가 진짜 맞는 문장을 보여준다** |

사용자가 「망명」을 입력했을 때:

```
1.  빈칸에 「망명」이 들어가 문장이 완성된다        (0.6초)
2.  문장이 교체된다
        그는 정치적 박해를 피해 프랑스로 [망명]했다.
3.  원래 문장으로 돌아오고 빈칸이 비워진다
```

**한 마디도 설명하지 않습니다.** *"네 단어는 이 문장의 것"*을 보여주고 원래 문제로 돌려보냅니다.

**왜 이게 진짜 차이인가**

- 글자를 지워도 다릅니다 — 한쪽은 말풍선 하나가 추가되고, 한쪽은 **문장이 바뀌었다 돌아옵니다**
- **우리 자산으로만 됩니다.** 1,390개 예문에서 「망명」이 target인 문항을 그대로 쓰면 됩니다. 없으면 짧은 대조 예문 하나를 `nuance`에 넣습니다
- **P38(예문에서 그 단어가 유일하게 잘 맞아야 한다)과 정확히 같은 축**입니다. 문항 기준이 곧 뉘앙스 기능이 됩니다

> **`docs/유의어_뉘앙스_설계.md`에 큰 함의가 있습니다.** 1,043건 주석이 **「설명문」이 아니라 「대조 예문」**이 되면 —
> ① 쓰기 쉽습니다 (설명을 짓는 것보다 예문을 고르는 게 빠릅니다)
> ② 품질 편차가 작습니다 (설명은 잘 쓰고 못 쓰고가 갈리지만 예문은 맞고 틀리고입니다)
> ③ **기존 문항을 재활용**할 수 있습니다

---

### 4-3. 근접 오답 — 그들의 대응물을 만들지 않습니다

말해보카는 **철자 근접도**를 줍니다 🔍 (`profiecie_c_ — 정답과 3글자 달라요`). 영어라서 성립합니다.

**한국어의 오답은 대개 철자가 아니라 「다른 낱말」입니다.** 그래서 *"몇 글자 다르다"*의 한국어판을 만들 이유가 없습니다. 그건 대응물을 억지로 만드는 것입니다.

대신 **오답의 종류에 따라 갈라집니다.**

| 사용자 입력 | 처리 |
|---|---|
| **다른 낱말** (「망명」) | **4-2 — 그 단어의 문장을 보여준다** |
| **맞춤법 오류** (「돼」/「되」, 「率」 관련 두음) | **맞춤법 자체가 콘텐츠입니다.** 이 앱이 존재하는 이유에 가깝습니다 |
| 단순 오타 | 조용히 입력창만 비운다 |

**맞춤법 교정은 그들에게 아예 없는 축입니다** — 외국어 학습자에게 「돼/되」에 해당하는 문제가 없기 때문입니다. **모어 앱만 가질 수 있는 기능**이고, 초판처럼 *"첫 글자는 맞았어"*로 문구만 바꾸는 것과는 종류가 다릅니다.

---

### 4-4. 복습 정보 — **주는 시점을 바꿉니다**

| | |
|---|---|
| 말해보카 🔍 | 문항 **상단 칩**에 「686일 전」 — **푸는 중에** 보임 |
| 한글마루 | **결과 화면**에 「오늘 되찾은 단어 4개」 — 푸는 중엔 아무 표시 없음 |

**같은 정보인데 시점이 감정을 바꿉니다.**

- 푸는 중에 「686일 전」이 뜨면 → *"그때 배웠는데 또 모르네"* — **압박**
- 다 풀고 나서 보면 → *"1년 만에 다시 떠올렸네"* — **성취**

초판에서 저는 이걸 *"「686일 전」 대신 「37일 만에 다시 만났네」"*로 적었습니다. **문구만 바꾼 것이었습니다.** 자리를 옮기는 게 진짜 차이입니다.

---

### 4-5. 격려·연출 — **안 하는 것이 형식입니다**

말해보카는 25/50 지점에서 **캐릭터가 튀어나와 문제를 가립니다** 🔍. 오답이면 **화면 전체가 붉어집니다.**

우리는 **하지 않습니다.** 진행 능선이 조용히 올라갈 뿐입니다.

초판의 *"「와우!! 잘 하고 있어요!」 대신 「반이나 왔네」"*는 **팝업을 그대로 두고 문구만 바꾼 것**이었습니다. 팝업을 만들지 않는 것이 차이입니다.

> **하랑이는 학습 흐름 밖에만 등장합니다** — 세션 시작·결과 화면·업적. 문제를 푸는 동안에는 **문장과 나만 있습니다.** 이건 P14(화면을 지배하지 않는다)의 구체판입니다.

---

### 4-6. 힌트 — **사는 것이 아니라 주는 것**

말해보카는 힌트가 **버튼 3개**(길이 보기 → 보너스 힌트 → 정답 보기)이고, 🤔 「보너스 힌트」는 재화 소비처로 보입니다.

**우리는 힌트를 팔지 않습니다.**

> ⚠️ **제 앞선 제안을 철회합니다.** `docs/UX_차별화_전략.md` 1절에서 *"파란 조각의 소비처를 힌트로 삼자"*고 썼는데, **그건 실수였습니다.** 힌트를 재화로 사게 하면 **막힌 순간에 비용을 물리는 구조**가 되고, 이는 *벌하지 않는다*(P17)와 정면으로 어긋납니다.

우리 방식:

- 힌트는 **틀린 뒤 자동으로 나옵니다.** 초성이 조용히 켜집니다
- 요청할 수도 있지만 **비용이 없습니다**
- 파란 조각의 소비처는 **꾸미기**여야 합니다 — 학습을 방해하지 않는 곳

**버튼 3개 vs 자동으로 켜지는 초성.** 글자를 지워도 다릅니다.

---

### 4-7. 발화 상황 — **요소를 늘리지 않고 겹칩니다**

말해보카는 문장 위에 **별도의 회색 한 줄**을 둡니다 🔍 (*"동작 감지 CCTV에 관해 설명하며"*).

우리는 **출처 표기(P45-1)에 그 일을 겸하게 합니다.**

```
신문 사설에서
   … 사이의 ____ 탓에 우리는 스스로를 자책하게 된다.
```

- 우리 예문은 논설조라 *"~하며"*가 애초에 안 붙습니다
- **화면 요소가 하나 적습니다.** 그들은 「상황 줄 + 출처 줄」 둘, 우리는 하나
- 저작권 대응(P45)과 문맥 제공이 **한 번에** 해결됩니다

---

### 4-8. 이건 차별화가 아닙니다 — **말투 통일**

`docs/브랜드_원칙_점검표.md` 충돌 6에서 짚은 **하랑이 반말 통일**은 여전히 해야 합니다. 다만 **차별화 항목이 아닙니다.**

- ✅ **브랜드 규칙(P12) 준수**이고 **내부 일관성** 회복입니다
- ❌ 그들과 달라 보이게 하는 효과는 **거의 없습니다.** 말풍선이 그대로면 말투를 바꿔도 같은 화면입니다

**앞 절들을 하면 말투 문제는 상당수 저절로 사라집니다** — 말풍선이 줄면 하랑이가 할 말도 줄기 때문입니다.

## 5. 하랑이 말투 통일 — **차별화가 아니라 브랜드 준수입니다** (4-8절 참고)

코드를 확인하다 발견했습니다. **하랑이의 말투가 화면마다 다릅니다.**

| 위치 | 현재 문구 | |
|---|---|---|
| 웰컴 말풍선 | *"안녕! 오늘도 같이 배워볼까?"* | ✅ 반말 |
| 유의어 재도전 | *"좋은 단어예요! 아까 본 단어를 떠올려 볼까요?"* | ❌ 해요체 |
| 재도전 정답 | *"아까 놓쳤던 단어를 다시 맞혔어요!"* | ❌ 해요체 |
| 조선어학회 칭호 | *"…분들의 이름이에요."* | ❌ 해요체 |

**브랜드 규칙은 반말입니다**(P12 · 브리핑 3절). 그리고 **말해보카도 해요체입니다.** 즉 지금 우리 문구는 **브랜드 규칙을 어기면서 동시에 그들과 닮아 있습니다.**

> 반말로 통일하면 **원칙을 지키고 내부 일관성을 회복**합니다. 비용은 문장 서너 개이고, **스크린샷에 찍히므로 촬영 전에** 하는 게 좋습니다.
>
> ⚠️ **다만 이걸 차별화로 세지 마세요.** 말풍선 구조가 그대로면 말투를 바꿔도 같은 화면입니다(4-8절). 진짜 차이는 4-2~4-7에 있습니다.

**단, 시스템 메시지는 해요체가 맞습니다** — *"네트워크 연결을 확인해 주세요"*는 하랑이가 하는 말이 아니라 앱이 하는 말입니다. **반말은 하랑이가 말할 때만.**

## 6. 마케팅에서의 태도

*"말해보카 국어판 아니냐"*는 반응은 **나옵니다.** 500만 다운로드는 우리 초기 이용자 상당수가 그 앱을 써 봤다는 뜻입니다.

**부인하지 마세요.** 방어적으로 굴수록 각인됩니다.

| 하지 말 것 | 대신 |
|---|---|
| *"저희는 다릅니다"* 하며 기능 차이를 나열 | *"영어 어휘 앱에서 배운 게 많습니다. 다만 모어는 다른 문제라서요."* |
| **"직접 타이핑"·"뉘앙스 구분"·"3단 판정"을 고유 발명처럼** (P48) | *"이미 잘 만들어진 방법을, 국어에 맞게 다시 팠습니다"* |
| 슬로건을 *"국어, 문제는 어휘야"* 류로 | 원문 구조를 따라가는 인상. **"나의 마지막 국어 공부"** 그대로 |
| 채점 단계를 **「비슷」**이라 부르기 | **「아깝다」** |
| *"20문제로 실력 진단"* | **결과(해발)**를 말하기 |

**정직이 가장 싼 방어입니다.** 벤치마킹을 인정하는 순간 *"베꼈다"*는 지적은 비판이 아니라 그냥 사실 확인이 되고, 대화는 *"그래서 뭐가 다른가"*로 넘어갑니다. 거기서부터가 우리 몫입니다.

## 7. 첫 세션 3분 안에 마주쳐야 할 것

첫인상은 닮아도 됩니다. **다른 물건이라는 인식은 첫 세션 안에 만들어야** 합니다.

1. **어휘 고도(해발 N m)** — 배치고사 결과가 산 일러스트와 함께 뜨는 순간
2. **오답 통계** — *"남들은 뭐라고 썼을까"*
3. **하랑이가 반말로 말을 거는 순간**
4. **틀렸는데 아무 일도 안 일어나는 경험** — 붉은 화면도, 하트가 깨지는 것도 없다

4번은 **안 만들어서 생기는 차별점**이라 비용이 0입니다.
